## 1. 设计目标与约束

| 目标 | 技术含义 |
| --- | --- |
| mock 数据与代理解耦 | 数据只存在项目 `mocks/` JSON；Whistle 不再用 Values 存 mock |
| 切 Scene 不丢数据 | 激活只改 `config.json.activeScenes` 与内存路由表，不删 `scenes/*.json` 与 `data/` |
| 切 Scene 不改规则 | 前缀规则稳定；匹配与透传在插件 `server` Hook 内完成 |
| 本机工具、可 git | 不引入数据库；工作区路径可配，数据跟业务仓库走 |
| 嵌进 Whistle | 管理面板走插件 Tab；不另起 `:3456` 进程 |

硬约束：

- Whistle `>= 2.9.100`（客户端 `>= 1.3.8`），脚手架 lack `>= 1.4.0`
- HTTPS 业务接口必须在 Whistle 开启 HTTPS 抓包，插件才能看到明文 path
- 插件包名必须是 `whistle.scene-mock`（或 `@scope/whistle.scene-mock`）
- `server` Hook 要接管请求，规则必须走**短协议** `scene-mock://`（长协议 `whistle.scene-mock://` 不能作为请求入口）

## 2. 关键架构决策

产品方案把 scene-mock 画成「独立 Node 进程 `:3456` + Whistle 一条前缀转发」。落地时改为 **Whistle 插件进程内处理**，原因如下。

### 2.1 用插件 `server` Hook 替代独立 mock 服务

[插件开发 · server](https://wproxy.org/docs/extensions/dev.html) 允许插件作为 server：直接响应，或处理后继续转发。官方示例（`whistle.test-server`）给出两种路径：

- 命中 mock：`res.writeHead` / `res.end` 直接返回
- 未命中：`req.passThrough()` 回源，或 `req.request()` 打到指定上游

这正好对应产品的「命中返回 Scene 返回值 / 未命中透传」。

独立 `:3456` 的问题：Whistle 把 `https://api.example.com/api/orders` 转成 `http://127.0.0.1:3456/api/orders` 后，**原始 host 丢失**，只能靠配置 `proxyTarget` 才能透传。插件 `server` Hook 拿到的是 `req.fullUrl` / `req.originalReq`，未命中可以直接 `passThrough` 回原地址，Cookie / Authorization 自然跟上。

### 2.2 用 `uiServer` 替代独立管理端口

插件操作界面默认地址：`http[s]://local.whistlejs.com/plugin.scene-mock/`。点击 Plugins 列表的 Option / 插件名即可打开（Tab 模式）。

管理 API 挂在 uiServer 下，与业务请求隔离：业务流量进 `server` Hook，面板流量进 `uiServer`。不再需要产品方案里的 `/__admin/*` 与业务 path 防撞。

前端静态资源必须用**相对路径**。Vite 的 `base` 设为 `'./'`，否则插件部署在 `/plugin.scene-mock/` 下会 404。依据：[插件页面内部路径规范](https://wproxy.org/docs/extensions/dev.html)。

### 2.3 用插件 `rules.txt` 替代「每次复制规则」

插件安装后自动加载 `rules.txt`，效果等同界面 Rules，**优先级低于界面 Rules**；插件被禁用立即失效。

插件根据工作区 `config.json.matchPatterns`（默认 `["/api/"]`）生成：

```
# generated by whistle.scene-mock — do not edit
/api/ scene-mock://
```

切 Scene **不改**这条规则。匹配哪条返回值由内存路由表决定。界面 Rules 若与插件规则冲突，以界面为准，避免抢用户已有配置。

### 2.4 数据仍在项目 `mocks/`，不进插件目录

插件安装在 Whistle 插件目录，业务 mock 必须留在前端仓库里才能 git 共享。因此插件启动后先绑定 **工作区根路径**（其下的 `mocks/`），路径记在插件 `localStorage`，不写进可提交的 `apis.json`。

## 3. 总体架构

```
浏览器 / App
    │
    ▼
Whistle
    ├─ HTTPS 解密（需开启抓包）
    ├─ 规则匹配
    │     插件 rules.txt:  /api/  scene-mock://     （短协议，入口）
    │     界面 Rules:      用户规则优先
    │
    ├─ server Hook（whistle.scene-mock）
    │     ├─ 命中激活 Scene 路由  →  delay + status/headers/body
    │     ├─ 未命中且配置了 proxyTarget → req.request(proxyTarget)
    │     └─ 未命中且未配置 proxyTarget → req.passThrough() 回源
    │
    └─ uiServer
          /plugin.scene-mock/          SPA 面板
          /plugin.scene-mock/cgi-bin/* Admin API

磁盘（业务仓库，可 git）
    mocks/apis.json
    mocks/config.json
    mocks/scenes/<scene-id>.json
    mocks/data/<api-id>/<variant>.json
```

四层对应产品，但运行时收敛为 **一个插件进程**（Whistle 加载）：

| 产品层级 | 技术落地 |
| --- | --- |
| 数据层 `mocks/` | `Store`：读写 JSON + `fs.watch` 热加载 |
| 服务层 mock 服务 | `server` Hook + `Matcher` + `RouteTable` |
| 交互层 Web 面板 | Vite SPA + `uiServer` |
| 接入层 whistle | 插件自身：`rules.txt` + 短协议 `scene-mock://` |

进程与端口：

- 不监听 `3456`。面板走 Whistle UI 端口（默认 `8899`）。
- 插件禁用 = 规则失效 = mock 立即停止，无需再停独立进程。
- 不再处理「3456 被占用」；插件加载失败由 Whistle 插件列表展示。

## 4. Whistle 插件能力映射

一期只用文档里与本产品直接相关的 Hook，其余明确不用，避免职责扩散。

| 插件能力 | 一期 | 用法 |
| --- | --- | --- |
| **server** | P0 必做 | 接收短协议请求；mock 或透传 |
| **uiServer** | P0 必做 | 面板静态资源 + `/cgi-bin/*` |
| **rules.txt** | P0 必做 | 按 `matchPatterns` 生成前缀规则；`options.updateRules()` 热更新 |
| statsServer | P1 | 命中日志：Scene / api-id / mock 或透传 |
| whistleConfig.networkColumn | P1 | Network 表增加 Scene 列 |
| whistleConfig.networkMenus | P1 | 右键「加入接口池 / 加入 Scene」 |
| rulesServer | 不做 | 只对「已匹配插件协议」的请求动态补规则；入口规则用 `rules.txt` 即可 |
| resRules / resRulesServer | 不做 | 返回值由 `server` 直接写，不走 resBody 协议 |
| auth / sniCallback / pipe | 不做 | 鉴权、证书、加解密不是本期职责 |
| Values / 插件变量 `%scene-mock=` | P1 可选 | 可用 `%scene-mock.dir=` 覆盖工作区路径 |

`package.json` 关键配置：

```json
{
  "name": "whistle.scene-mock",
  "whistleConfig": {
    "hideLongProtocol": true,
    "favicon": "/public/favicon.png",
    "priority": 0
  }
}
```

- `hideLongProtocol: true`：Rules 补全只暴露短协议 `scene-mock://`，避免用户误用长协议导致 `server` Hook 收不到请求。
- 不设 `noOption`，保留 Option 入口。
- 不设 `openInModal`：面板有 Scene 列表、编辑器、冲突弹窗，用默认 Tab。
- Vite `base: './'`，页面内 API 一律相对路径 `./cgi-bin/...`。

## 5. 工程结构

仓库同时是 npm 插件包。核心逻辑与 Whistle 适配层分开，方便单测时不启动 Whistle。

```
scene-mock/                          # git 仓库根 = 插件根
├── package.json                     # name: whistle.scene-mock
├── rules.txt                        # 运行时由插件回写，仓库内放注释模板
├── tsconfig.json
├── src/
│   ├── index.ts                     # 导出 server / uiServer
│   ├── server.ts                    # server Hook
│   ├── rules.ts                     # 生成 rules.txt + updateRules
│   ├── uiServer/
│   │   ├── index.ts                 # Koa 挂到 uiServer
│   │   ├── router.ts                # /cgi-bin/*
│   │   └── sse.ts                   # 热加载 / 冲突推送到面板
│   └── core/                        # 零 Whistle 依赖，可单独测
│       ├── types.ts
│       ├── store.ts                 # 读盘、写盘、watch、坏文件隔离、variant 引用计数 / fork
│       ├── matcher.ts               # method + :param
│       ├── route-table.ts           # 由 activeScenes 合成生效路由
│       └── conflict.ts              # api-id 重合检测与二选一
├── web/                             # 管理面板（Vite + React）
│   ├── vite.config.ts               # base: './'
│   └── src/
├── test/
│   ├── matcher.test.ts
│   ├── route-table.test.ts
│   ├── conflict.test.ts
│   └── store.test.ts
└── fixtures/mocks/                  # 单测与本地演示用示例数据
```

导出形态（lack / Whistle 约定）：编译后 `dist/server.js`、`dist/uiServer/index.js`，`package.json` 的 `whistleConfig` 不需要列出 Hook 名——Whistle 按文件名加载 `server`、`uiServer`（lack 脚手架生成的入口即如此）。

`src/index.ts` 若采用单入口，则：

```ts
export { default as server } from './server';
export { default as uiServer } from './uiServer';
```

以 lack `lack init server,uiServer` 生成的目录为准，不要同时维护两套入口。

模块边界：

- `core/*` 禁止 `import` 任何 `Whistle.*` 类型。
- `server.ts` 只做适配：从 `req.originalReq` 取 method / path，调 `RouteTable.match`，再 `res.end` 或 `req.passThrough`。
- `uiServer` 只通过 `Store` 读写文件，不直接改 `RouteTable`；Store 变更后路由表重算。

共享状态：Whistle 在同一插件进程里调用两个 Hook，用模块单例 `createAppContext()` 保存 `Store` / `RouteTable` / `mocksRoot`。不要把路由表塞进 `options.localStorage`（那是持久化 KV，不适合热路径）。

## 6. 数据层

文件协议与产品方案第 6 章一致，此处只补技术约定。

### 6.1 工作区绑定

```
mocksRoot = <用户选择的项目根>/mocks
```

解析顺序：

1. 插件 `localStorage` 键 `mocksRoot`（面板「选择工作区」写入）
2. P1：规则变量 `%scene-mock.dir=/abs/path`
3. 均无：不生成劫持规则，面板提示选择目录；`server` Hook 即使被界面 Rules 强行命中，也一律 `passThrough`

`localStorage` 用 `options.localStorage`（插件私有、重启保留）。不要用 `sharedStorage`。

校验：目录必须存在且可读；不存在则面板报错，不自动 `mkdir` 出一套空 mocks（避免绑错路径后污染磁盘）。首次使用提供「初始化 mocks 骨架」按钮，用户确认后再写 `apis.json` / `config.json` / 空的 `scenes/` 与 `data/`。

### 6.2 `config.json` 字段（相对产品方案的增补）

```json
{
  "proxyTarget": "",
  "activeScenes": ["normal-order"],
  "matchPatterns": ["/api/"],
  "unmatched": "passthrough"
}
```

| 字段 | 说明 |
| --- | --- |
| `proxyTarget` | 空：未命中走 `passThrough`。非空：未命中 `req.request` 到该 origin（保留 path/query/body） |
| `activeScenes` | 与产品一致；建议 gitignore 或后期用 `config.local.json` 覆盖 |
| `matchPatterns` | 写入插件 `rules.txt` 的 pattern 列表，语法即 Whistle pattern |
| `unmatched` | `passthrough`（默认）或 `404`。`404` 对齐产品「未配透传则明确失败」，给「想确认哪些接口没 mock」用 |

**删除产品方案中的 `port`**。端口由 Whistle 管理，写了也无效。

### 6.3 写盘规则

- 所有写操作先校验 JSON schema，再 `writeFile` 原子替换（写 `*.tmp` + `rename`），避免半包文件被 watch 读到。
- 接口 id、Scene 文件名（不含 `.json`）、variant 名：`^[a-zA-Z][a-zA-Z0-9_-]*$`，禁止 `/`、`..`、`.`，防止路径穿越。
- 重命名 api-id：事务顺序为「`data/<old>/` 改名为 `data/<new>/` → 改所有 `scenes/*.json` 的 `apis` 键 → 改 `apis.json` → 删旧目录」。中途失败在面板报「重命名未完成」，不静默半更新。
- Scene JSON 与 data 文件落盘时 `JSON.stringify(doc, null, 2)`，保证 git diff 稳定。
- data 文件的内容就是响应体本身（object / array / string / number / bool / `null`），不要再包一层 `{ "body": ... }`。

### 6.4 内存模型

```ts
type ApiDef = { id: string; method: string; url: string; desc?: string };

type SceneApiEntry = {
  status?: number;                         // default 200
  delay?: number;                          // ms, default 0
  headers?: Record<string, string>;
  data: string;                            // variant 名 → data/<apiId>/<data>.json
};

type SceneDef = {
  id: string;                              // 文件名 scenes/<id>.json
  name: string;
  desc?: string;
  apis: Record<string, SceneApiEntry>;     // api-id → 条目
};

type ResponseDoc = {
  status?: number;
  delay?: number;
  headers?: Record<string, string>;
  variant: string;
  body?: unknown;                          // 从 data 文件读入
};

type CompiledRoute = {
  apiId: string;
  sceneId: string;
  variant: string;
  method: string;
  pattern: string;
  regex: RegExp;
  staticScore: number;
  response: ResponseDoc;
};
```

`Store` 另持一份 `dataIndex: Map<apiId, Map<variant, unknown>>`。引用计数：扫全部 `scenes/*.json` 的 `apis.*.data`。

`RouteTable` 只包含：**激活 Scene ∩ 条目含 `data` ∩ 对应 data 文件存在**。声明了接口但未设 `data`、或 variant 文件缺失 → 不进表（产品：不算生效路由，走未命中）。

合成：

```
for sceneId in activeScenes:
  for [apiId, entry] of Object.entries(scene.apis):
    body = dataIndex.get(apiId)?.get(entry.data)
    if body === undefined: skip          // 文件不存在；合法 JSON `null` 仍进表
    emit CompiledRoute { ...entry, body, variant: entry.data }
```

### 6.5 隔离、复制与 fork

面板默认隔离，避免改一份 data 覆盖其它 Scene（产品 6.4）。Store 实现：

| 操作 | 行为 |
| --- | --- |
| 新建 Scene 条目 | 默认新建 `data/<api-id>/<variant>.json`。variant 优先用调用方传入的语义名；缺省用 `sceneId`，若已占用则 `sceneId-2`… |
| 复制其它 Scene | 复制源 data 文件为新 variant，再写入本 Scene 的 `data` 字段。不改为指向源文件 |
| 写 body | `usedBy.length > 1` → 先复制成新 variant、改本 Scene 引用，再写新文件（fork）。`usedBy.length <= 1` → 原地覆盖 |
| 显式共享 | 只改 Scene 条目的 `data` 指向已有 variant，不复制文件 |
| 删除 Scene | 只删 `scenes/<id>.json`；孤立 variant **不自动删**，详情接口返回 `orphans[]` 供面板提示清理 |
| 删除接口（force） | 从各 Scene 去掉该 api-id 键，并删除 `data/<api-id>/` |

fork 后返回 `{ forked: true, variant }`，面板把路径切到新文件。手改共享 data 文件不走 fork（热加载按引用全部生效），面板顶部可提示引用计数。

## 7. 匹配引擎

输入：`method`、`pathname`（不含 query）。`pathname` 从 `req.fullUrl` 解析，去掉 origin。Whistle 已把 HTTPS 解成明文 URL，**不要用 Host 头拼 path**。

规则（与产品 7.1 一致）：

1. method 大小写不敏感精确相等
2. path 匹配 URL 模式；`:param` 只吃单段 `[^/]+`；模式必须整段匹配（`^...$`）
3. 忽略 query
4. 不匹配 host（host 过滤交给 Whistle pattern，如 `^https?://api\.example\.com/api/`）

编译：

```
/api/users/:id  →  ^/api/users/([^/]+)$
```

冲突优先级（不同 api-id 模式重叠）：

1. `staticScore` 大者胜（静态段数量，`/api/users/me` > `/api/users/:id`）
2. 同分：`apis.json` 中先出现者胜
3. 同分且并存时，面板 `status.ambiguousRoutes` 提示，**不弹 Scene 冲突窗**

`:param` 一期只用于匹配，不注入 body（动态模板是 P2）。

复杂度：生效路由通常几十～几百条，线性扫描足够。路由表在激活/热加载时编译一次，请求路径只做 `regex.test`。

## 8. server Hook：请求处理

签名与官方一致：

```ts
export default (server: Whistle.PluginServer, options: Whistle.PluginOptions) => {
  server.on('request', handleHttp);
  server.on('upgrade', (req, socket) => req.passThrough()); // 一期 WebSocket 透传
  server.on('connect', (req, socket) => req.passThrough()); // tunnel 不处理
};
```

### 8.1 HTTP 处理流程

```
request
  │
  ├─ 无 RouteTable（未绑定工作区） → passThrough
  ├─ method + pathname 匹配
  │     ├─ hit → drain(req) → wait(delay) → writeHead + end(body)
  │     └─ miss
  │           ├─ unmatched=404 且无 proxyTarget → 404 JSON
  │           ├─ proxyTarget 非空 → req.request(upstream) 管道转发
  │           └─ 默认 → req.passThrough()
```

**必须先 drain 请求体**再结束响应（官方 `whistle.test-server` 的 `drain` 模式）。否则客户端 POST 可能挂起。

mock 响应：

```ts
const status = response.status ?? 200;
const headers = { 'content-type': 'application/json', ...response.headers };
headers['x-scene-mock'] = `${sceneId}/${apiId}/${variant}`;  // 便于 Network 一眼看出走了 mock
const body = serialize(response.body, headers['content-type']);
```

`delay` 用 `setTimeout`，只作用于 mock 命中；透传不额外加延迟。延迟期间不阻塞其它请求（每个 request 独立）。

### 8.2 透传两种实现

**A. `req.passThrough()`（默认）**

未命中、且 `proxyTarget` 为空。Whistle 继续访问 `fullUrl` 原始目标。这是混合联调的主路径，也是相对独立 `:3456` 方案最大的简化。

**B. `req.request()` + pipe（配置了 `proxyTarget`）**

把请求打到 `proxyTarget + pathname + search`。实现注意：

- 去掉 hop-by-hop：`Connection`、`Keep-Alive`、`Transfer-Encoding`、`TE`、`Trailer`、`Upgrade`、`Proxy-Authorization`、`Proxy-Authenticate`
- `Host` 改为 `proxyTarget` 的 host
- 保留 `Cookie`、`Authorization`
- 超时 30s；失败 `502`，body 为 `{ error: 'proxy_failed', message }`
- HTTPS 上游用 Whistle 提供的 `req.request`，不要自己再起 undici 绕过代理证书

WebSocket / CONNECT 一期直接 `passThrough`，与产品边界「不做 WebSocket」一致。

### 8.3 响应体序列化

| Content-Type | body 类型 | 输出 |
| --- | --- | --- |
| `application/json`（默认） | 任意 JSON 值 | `JSON.stringify` |
| `text/*` | string | 原样 |
| 其它 | string 或已是 string 的 JSON | 若非 string 则 stringify |

非法 `delay`（负、NaN）按 0；`status` 非 100–599 按 200，并记入热加载警告（文件仍服务，不丢）。

## 9. 规则下发

### 9.1 生成内容

`src/rules.ts` 根据 `matchPatterns` 生成插件根目录 `rules.txt`：

```
# generated by whistle.scene-mock — do not edit
/api/ scene-mock://
```

多前缀则多行。pattern 原样写出，**不在插件里实现 Whistle 的 pattern 解析**——那是 Whistle 的事。

生成后调用 `options.updateRules()`，使新规则生效而无需重装插件。

### 9.2 何时更新

- 绑定 / 更换 `mocksRoot`
- `config.json` 的 `matchPatterns` 变化（面板保存或热加载）
- 插件启用时做一次

**不**在 Scene 激活时更新。切 Scene 只改内存 `RouteTable`。

### 9.3 空规则

未绑定工作区，或 `matchPatterns: []`：`rules.txt` 只保留注释。此时只有用户在界面 Rules 手写 `xxx scene-mock://` 才会进 `server` Hook。

### 9.4 与「复制规则」并存

面板仍提供「复制 whistle 规则」（产品 P0），文案改为：

- 默认：插件已自动写入 `rules.txt`，一般不用粘贴
- 若界面 Rules 里有更高优先级的同 pattern，复制内容给用户手动对齐

复制文本示例：

```
# scene-mock · 短协议才会进插件 server
# 插件禁用后这条（以及插件 rules.txt）都失效
/api/ scene-mock://
```

## 10. uiServer：管理面板与 Admin API

### 10.1 挂载方式

```ts
export default (server: Whistle.PluginServer, options: Whistle.PluginOptions) => {
  const app = new Koa();
  // cgi-bin 路由 + 静态 SPA
  server.on('request', app.callback());
};
```

lack 脚手架默认 Koa + `@koa/router`，沿用，避免再引入 Express。

静态目录指向 `web/dist`。SPA fallback：非 `/cgi-bin` 的 GET 回 `index.html`。

### 10.2 Admin API

前缀一律 `/cgi-bin`（Whistle 插件惯例）。面板用相对路径 `./cgi-bin/scenes`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/cgi-bin/workspace` | `{ mocksRoot, bound, errors[] }` |
| PUT | `/cgi-bin/workspace` | `{ mocksRoot }` 绑定并加载 |
| POST | `/cgi-bin/workspace/init` | 在已绑定路径写入空骨架 |
| GET | `/cgi-bin/status` | 激活列表、路由数、坏文件、歧义路由、冲突待处理 |
| GET | `/cgi-bin/apis` | 接口池（含 `usedBy: sceneId[]`） |
| POST | `/cgi-bin/apis` | 注册 |
| PUT | `/cgi-bin/apis/:id` | 编辑；改 id 走重命名事务 |
| DELETE | `/cgi-bin/apis/:id?force=1` | 仍被引用时无 force 返回 409 + scene 清单 |
| GET | `/cgi-bin/scenes` | 列表（名称、接口数、是否激活、mtime） |
| POST | `/cgi-bin/scenes` | `{ id, name, desc }` → 写 `scenes/<id>.json`，`apis` 为空对象 |
| GET | `/cgi-bin/scenes/:id` | 详情 + 条目（method、URL、status、delay、variant、dataPath、refCount、是否缺文件） |
| PUT | `/cgi-bin/scenes/:id` | 改 name / desc；增删 `apis` 键（不在此写 body） |
| DELETE | `/cgi-bin/scenes/:id` | 删 `scenes/<id>.json`；若在 activeScenes 则一并移除；响应可带 `orphans[]` |
| PUT | `/cgi-bin/scenes/:id/apis/:apiId` | 写条目 `{ status, delay, headers, data?, body? }`。有 `body` 时按 6.5 fork；无 `data` 则新建 variant |
| POST | `/cgi-bin/scenes/:id/apis/:apiId/copy` | `{ fromSceneId }`：复制源 data 文件为新 variant 并写入本条目 |
| PUT | `/cgi-bin/scenes/:id/apis/:apiId/share` | `{ variant }`：显式指向已有 variant，不复制 |
| GET | `/cgi-bin/data/:apiId` | 该接口全部 variant 及 `usedBy: sceneId[]` |
| PUT | `/cgi-bin/data/:apiId/:variant` | 直接写 body。`usedBy.length > 1` 时 409，除非 `?fork=1`（复制后写，需带 `sceneId`） |
| DELETE | `/cgi-bin/data/:apiId/:variant` | 仍被引用则 409；孤立文件才删 |
| POST | `/cgi-bin/activate` | `{ sceneId }` → 200 或 409 冲突载荷 |
| POST | `/cgi-bin/activate/resolve` | `{ sceneId, action: "keep-new" \| "keep-old" }` |
| POST | `/cgi-bin/deactivate` | `{ sceneId }` 直接移除，不弹窗 |
| GET | `/cgi-bin/config` | 去掉内部字段的 config |
| PUT | `/cgi-bin/config` | `proxyTarget` / `matchPatterns` / `unmatched` |
| GET | `/cgi-bin/whistle-rules` | `{ text }` 供复制 |
| GET | `/cgi-bin/events` | SSE：`reload` / `error` / `conflict` |

统一错误体：

```json
{ "error": "conflict_pending", "message": "...", "details": {} }
```

HTTP：校验失败 400，资源不存在 404，接口仍被引用 / Scene 冲突 / 共享 variant 未 fork 409，工作区未绑定 412，写盘失败 500。

### 10.3 SSE

`text/event-stream`，事件：

- `reload`：文件已热加载，面板重拉列表
- `error`：坏 JSON，`{ path, reason }`
- `conflict`：热加载发现 `activeScenes` 自相冲突，面板强制打开冲突窗

面板隐藏时允许断开，可见时重连。不把 SSE 当请求日志通道（日志走 P1 statsServer）。

## 11. 热加载、错误与进程稳定性

监听 `mocksRoot` 递归（Node 18+ `fs.watch({ recursive: true })`，macOS / Windows 可用）。事件合并 **150ms debounce**，目标「保存后 200ms 内对新请求生效」。

按文件类型增量重载：

| 路径 | 动作 |
| --- | --- |
| `apis.json` | 重载接口池，重编译全表 |
| `config.json` | 重载激活与 matchPatterns；patterns 变则 `updateRules()` |
| `scenes/*.json` | 重载该 Scene（文件名 = scene-id）；重算引用计数并重编译相关路由 |
| `data/<api-id>/<variant>.json` | 更新 `dataIndex`；替换所有引用该 variant 的 `CompiledRoute.response.body` |
| `scenes/` 或 `data/` 下文件增删 | 重建 Scene 列表 / dataIndex，再按需重编译 |

坏文件策略（产品 6.6）：

- 解析失败 / schema 失败：**保留上一份合法内存快照**继续服务
- 把 `{ relativePath, reason }` 放进 `Store.errors`，SSE 推 `error`，面板顶部展示
- **不**抛出到 Hook 外；Whistle 文档说明插件未捕获异常不会打崩 Whistle，但仍应自己 catch，避免当前请求 500 且无说明
- 单个 data 文件损坏：只影响引用它的接口；其它 Scene / variant 继续服务
- 某个 `scenes/<id>.json` 损坏：只停用该 Scene（从路由表去掉），其它 Scene 继续
- `apis.json` / `config.json` 从未成功加载过：绑定失败，面板不可操作 mock，`rules.txt` 不劫持（避免空路由静默跑）

`config.json` 里 `activeScenes` 自相冲突（手改或 git merge）：

- 拒绝使用该激活集合
- `RouteTable` 清空（全部透传），避免歧义 mock
- SSE `conflict`，面板强制解决后再写回合法 `activeScenes`

## 12. 激活与冲突

实现放在 `core/conflict.ts`，uiServer 只负责把结果变成 409 + 弹窗。

`POST /cgi-bin/activate`：

1. 计算 `newApis = Object.keys(scene.apis)` 中「`data` 已设且 data 文件存在」的集合
2. 与每个已激活 Scene 求 api-id 交集
3. 无交集：`activeScenes.push`，写盘，重建路由表，200
4. 有交集：不改盘，409

```json
{
  "error": "scene_conflict",
  "incoming": { "id": "order-error", "name": "下单异常流" },
  "conflicts": [
    {
      "apiId": "get-orders",
      "method": "GET",
      "url": "/api/orders",
      "existingScene": { "id": "normal-order", "name": "正常下单", "status": 200, "preview": "{...}" },
      "incomingScene": { "status": 500, "preview": "{...}" }
    }
  ],
  "closeScenesIfKeepNew": ["normal-order"]
}
```

`preview`：对应 data 文件 JSON.stringify 截断到 200 字符。冲突比较的是「激活后会生效的合成响应」，不是 Scene JSON 本身。

`POST /cgi-bin/activate/resolve`：

- `keep-new`：从 `activeScenes` 去掉 `closeScenesIfKeepNew`（仅冲突的旧 Scene），加入新 Scene；无交集的已激活 Scene 不动
- `keep-old`：不改 `activeScenes`

不做按接口拆分。`deactivate` 直接删 id。

并发：激活用 Store 上的异步互斥队列（同一工作区串行写 `config.json`），防止双击开关写出交错数组。

## 14. 与产品方案的差异

产品语义不变。运行时形态有意调整：

| 点 | 产品方案 | 本技术方案 | 原因 |
| --- | --- | --- | --- |
| 进程 | 独立 Node `:3456` | Whistle 插件进程 | 用官方 `server` Hook，免端口与转发丢 host |
| 管理入口 | `http://127.0.0.1:3456/` | `/plugin.scene-mock/` | uiServer Tab |
| 管理 API | `/__admin/*` | `/cgi-bin/*` | 与业务流量物理隔离，遵循插件惯例 |
| 未命中默认 | 无 `proxyTarget` → 404 | `passThrough` 回源 | 插件仍持有 `fullUrl` |
| `config.port` | 有 | 删除 | 无独立监听端口 |
| `matchPatterns` | 无（复制规则） | 有，写入 `rules.txt` | 插件可自动加载规则 |
| 启动命令 | `npx scene-mock` | 安装/挂载插件 + `lack watch`（开发） | 生命周期归 Whistle |
| 一期「不自动改 Whistle 配置」 | 只复制 | 改插件自己的 `rules.txt`，不改用户界面 Rules | 仍不碰用户规则文件 |

`proxyTarget` 保留，用于「未 mock 的接口统一打到 staging」这类与浏览器地址栏 host 不同的上游。

## 18. 一期实现拆分

建议顺序，每步都可 `lack watch` 验证：

| 步 | 交付 | 验收 |
| --- | --- | --- |
| 1 | lack 脚手架 + `server` 对 `scene-mock://` 固定返回 hello | 界面规则 `example.com scene-mock://` 能打到插件 |
| 2 | `core/store` + 绑定工作区 + 读 `apis.json` / `scenes/*.json` / `data/` | 单测 + 面板能列出 Scene |
| 3 | `matcher` + `route-table` + server 真正 mock | 激活后接口返回 JSON，含 delay |
| 4 | miss → passThrough / proxyTarget / 404 | 未覆盖接口行为符合 config |

| 6 | Scene/接口/返回值 CRUD API + 面板六屏 + fork | 不打开编辑器能完成日常联调；共享数据从面板改会复制新文件 |
| 7 | 激活冲突 409 + 弹窗二选一 | 有交集必须确认；无交集并行 |

## 19. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 用户误用长协议 `whistle.scene-mock://`，`server` 收不到请求 | `hideLongProtocol: true`；复制规则只给短协议；文档强调 |
| `rules.txt` 写进 npm 全局目录失败（权限） | 失败则面板展示错误，并降级为「只复制规则」；不静默 |
| 界面 Rules 里已有 `/api/ file://...`，优先级盖过插件 | 配置页检测并提示「界面规则优先」；不自动改用户 Rules |
| 前缀过宽，所有 `/api/` 进插件 | 未命中默认 `passThrough`，源站仍可用；透传失败给 502 不是空白 |
| HTTPS 未开抓包，插件只能看到 CONNECT | 配置页检测 `options.getHttpsStatus`，未开启则横幅提示 |
| `fs.watch` 在部分 Linux 无 recursive | 对 `scenes/` 与每个 `data/<api-id>/` 逐目录 watch；或 P1 再引入 chokidar |
| 工作区路径绑错 | 不自动创建 mocks；展示将监听的绝对路径，确认后才 watch |
| 共享 variant 被手改 | 热加载按引用全部生效（与面板 fork 不同）；面板展示 refCount，手改路径旁提示 |
| `activeScenes` 被 commit 互相覆盖 | README 约定不提交该字段；P1 `config.local.json` |
| 插件热重载丢内存态 | 激活态以磁盘 `config.json` 为准，重载后重新 `Store.load` |
| 相对路径被 Vite 打成 `/assets/xxx` | `base: './'`；CI 检查 `web/dist/index.html` 不含以 `/assets` 开头的引用 |
