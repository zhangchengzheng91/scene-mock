# scene-mock 技术方案

基于 [产品方案](./product-proposal.md)，把 scene-mock 实现为 **Whistle 插件**。本文只覆盖实现决策、模块边界与接口约定；产品语义（项目、接口池、Scene、冲突二选一、JSON 落盘）以产品方案为准，不在此重复论证。

核心模型：**whistle 代理基于项目维度**。一个项目 = 一对域名（被代理的域名 → 代理到的域名）+ 一条 whistle 规则；选定项目后在其下新建 Scene，Scene 下维护每个请求的具体返回值。

插件开发能力对齐官方文档：[插件开发](https://wproxy.org/docs/extensions/dev.html)。

## 1. 设计目标与约束

| 目标 | 技术含义 |
| --- | --- |
| mock 数据与代理解耦 | 数据只存在项目 `mocks/` JSON；Whistle 不再用 Values 存 mock |
| 代理按项目维度 | 每个项目 = 被代理域名 + 代理到的域名；规则按项目生成；路由表按项目隔离 |
| 切 Scene 不丢数据 | 激活只改 `project.json.activeScenes` 与内存路由表，不删 `scenes/*.json` 与 `data/` |
| 切 Scene / 切项目不改规则 | 项目规则稳定（仅项目增删改 host 时增减）；匹配与透传在插件 `server` Hook 内完成 |
| 本机工具、可 git | 不引入数据库；工作区路径可配，数据跟业务仓库走 |
| 嵌进 Whistle | 管理面板走插件 Tab；不另起 `:3456` 进程 |

硬约束：

- Whistle `>= 2.9.100`（客户端 `>= 1.3.8`），脚手架 lack `>= 1.4.0`
- HTTPS 业务接口必须在 Whistle 开启 HTTPS 抓包，插件才能看到明文 path
- 插件包名必须是 `whistle.scene-mock`（或 `@scope/whistle.scene-mock`）
- `server` Hook 要接管请求，规则必须走**短协议** `scene-mock://`（长协议 `whistle.scene-mock://` 不能作为请求入口）

## 2. 关键架构决策

### 2.1 用插件 `server` Hook 替代独立 mock 服务

[插件开发 · server](https://wproxy.org/docs/extensions/dev.html) 允许插件作为 server：直接响应，或处理后继续转发。官方示例（`whistle.test-server`）给出两种路径：

- 命中 mock：`res.writeHead` / `res.end` 直接返回
- 未命中：`req.passThrough()` 回源，或 `req.request()` 打到指定上游

这正好对应产品的「命中返回 Scene 返回值 / 未命中透传到项目 target」。

独立 `:3456` 的问题：Whistle 把 `https://microcredit-ms-test-c.jhjj.paas.test/api/orders` 转成 `http://127.0.0.1:3456/api/orders` 后，**原始 host 丢失**，项目定位与按项目透传都无从谈起。插件 `server` Hook 拿到的是 `req.fullUrl` / `req.originalReq`，host 完整保留：先按 host 定位项目，未命中再 `req.request(project.target)` 或 `passThrough`，Cookie / Authorization 自然跟上。

### 2.2 用 `uiServer` 替代独立管理端口

插件操作界面默认地址：`http[s]://local.whistlejs.com/plugin.scene-mock/`。点击 Plugins 列表的 Option / 插件名即可打开（Tab 模式）。

管理 API 挂在 uiServer 下，与业务请求隔离：业务流量进 `server` Hook，面板流量进 `uiServer`。不再需要产品方案里的 `/__admin/*` 与业务 path 防撞。

前端静态资源必须用**相对路径**。Vite 的 `base` 设为 `'./'`，否则插件部署在 `/plugin.scene-mock/` 下会 404。依据：[插件页面内部路径规范](https://wproxy.org/docs/extensions/dev.html)。

### 2.3 用插件 `rules.txt` 按项目下发规则

插件安装后自动加载 `rules.txt`，效果等同界面 Rules，**优先级低于界面 Rules**；插件被禁用立即失效。

插件根据工作区全局 `matchPatterns`（默认 `["/api/"]`）+ **各项目的被代理域名** 生成：

```
# generated by whistle.scene-mock — do not edit
/api/ scene-mock://
microcredit-ms-test-c.jhjj.paas.test scene-mock://
```

切 Scene **不改**这些规则；只有项目新建 / 删除 / 改 host、或 `matchPatterns` 变化时才重写下发。匹配哪条返回值由内存中该项目的路由表决定。界面 Rules 若与插件规则冲突，以界面为准，避免抢用户已有配置。

### 2.4 数据仍在项目 `mocks/`，不进插件目录

插件安装在 Whistle 插件目录，业务 mock 必须留在前端仓库里才能 git 共享。因此插件启动后先绑定 **工作区根路径**（其下的 `mocks/`），路径记在插件 `localStorage`，不写进可提交的 JSON。

## 3. 总体架构

```
浏览器 / App
    │
    ▼
Whistle
    ├─ HTTPS 解密（需开启抓包）
    ├─ 规则匹配
    │     插件 rules.txt:  /api/ scene-mock://           （全局前缀，可选）
    │                      <项目host> scene-mock://      （每个项目一条）
    │     界面 Rules:      用户规则优先
    │
    ├─ server Hook（whistle.scene-mock）
    │     ├─ 按 req host 定位项目（未知 host → 透传并记录 unresolvedHosts）
    │     ├─ 命中该项目激活 Scene 路由  →  delay + status/headers/body
    │     ├─ 未命中且项目配了 target   →  req.request(project.target)
    │     └─ 未命中且未配 target       →  req.passThrough() 回源（或 unmatched=404）
    │
    └─ uiServer
          /plugin.scene-mock/          SPA 面板
          /plugin.scene-mock/cgi-bin/* Admin API

磁盘（业务仓库，可 git）
    mocks/config.json                                  # 全局：matchPatterns / unmatched
    mocks/projects/<project-id>/project.json           # 项目：name / host / target / activeScenes
    mocks/projects/<project-id>/apis.json              # 项目接口池
    mocks/projects/<project-id>/scenes/<scene-id>.json
    mocks/projects/<project-id>/data/<api-id>/<variant>.json
```

四层对应产品，但运行时收敛为 **一个插件进程**（Whistle 加载）：

| 产品层级 | 技术落地 |
| --- | --- |
| 数据层 `mocks/` | `Store`：读写 JSON + `fs.watch` 热加载（按项目分片） |
| 服务层 mock 服务 | `server` Hook + `ProjectResolver` + `Matcher` + 按项目的 `RouteTable` |
| 交互层 Web 面板 | Vite SPA + `uiServer` |
| 接入层 whistle | 插件自身：`rules.txt`（matchPatterns + 项目 host）+ 短协议 `scene-mock://` |

进程与端口：

- 不监听 `3456`。面板走 Whistle UI 端口（默认 `8899`）。
- 插件禁用 = 规则失效 = mock 立即停止，无需再停独立进程。
- 不再处理「3456 被占用」；插件加载失败由 Whistle 插件列表展示。

## 4. Whistle 插件能力映射

一期只用文档里与本产品直接相关的 Hook，其余明确不用，避免职责扩散。

| 插件能力 | 一期 | 用法 |
| --- | --- | --- |
| **server** | P0 必做 | 接收短协议请求；项目定位、mock 或透传 |
| **uiServer** | P0 必做 | 面板静态资源 + `/cgi-bin/*` |
| **rules.txt** | P0 必做 | 按 `matchPatterns` + 项目 host 生成规则；`options.updateRules()` 热更新 |
| statsServer | P1 | 命中日志：项目 / Scene / api-id / mock 或透传 |
| whistleConfig.networkColumn | P1 | Network 表增加 项目 / Scene 列 |
| whistleConfig.networkMenus | P1 | 右键「加入接口池 / 加入 Scene」 |
| rulesServer | 不做 | 只对「已匹配插件协议」的请求动态补规则；入口规则用 `rules.txt` 即可 |
| resRules / resRulesServer | 不做 | 返回值由 `server` 直接写，不走 resBody 协议 |
| auth / sniCallback / pipe | 不做 | 鉴权、证书、加解密不是本期职责 |
| Values / 插件变量 `%scene-mock=` | P1 可选 | 可用 `%scene-mock.dir=` 覆盖工作区路径 |

`package.json` 关键配置：

```json
{
  "name": "whistle.scene-mock",
  "whistleConfig": {
    "hideLongProtocol": true,
    "favicon": "/public/favicon.png",
    "priority": 0
  }
}
```

- `hideLongProtocol: true`：Rules 补全只暴露短协议 `scene-mock://`，避免用户误用长协议导致 `server` Hook 收不到请求。
- 不设 `noOption`，保留 Option 入口。
- 不设 `openInModal`：面板有项目 / Scene 列表、编辑器、冲突弹窗，用默认 Tab。
- Vite `base: './'`，页面内 API 一律相对路径 `./cgi-bin/...`。

## 5. 工程结构

仓库同时是 npm 插件包。核心逻辑与 Whistle 适配层分开，方便单测时不启动 Whistle。

```
scene-mock/                          # git 仓库根 = 插件根
├── package.json                     # name: whistle.scene-mock
├── rules.txt                        # 运行时由插件回写，仓库内放注释模板
├── tsconfig.json
├── src/
│   ├── index.ts                     # 导出 server / uiServer
│   ├── server.ts                    # server Hook
│   ├── rules.ts                     # 生成 rules.txt + updateRules
│   ├── uiServer/
│   │   ├── index.ts                 # Koa 挂到 uiServer
│   │   ├── router.ts                # /cgi-bin/*
│   │   └── sse.ts                   # 热加载 / 冲突推送到面板
│   └── core/                        # 零 Whistle 依赖，可单独测
│       ├── types.ts
│       ├── store.ts                 # 读盘、写盘、watch、坏文件隔离、variant 引用计数 / fork
│       ├── project.ts               # 项目 CRUD、host 唯一性校验、host→项目 解析
│       ├── matcher.ts               # method + :param
│       ├── route-table.ts           # 由各项目 activeScenes 分别合成生效路由
│       └── conflict.ts              # api-id 重合检测与二选一（项目内）
├── web/                             # 管理面板（Vite + React）
│   ├── vite.config.ts               # base: './'
│   └── src/
├── test/
│   ├── matcher.test.ts
│   ├── project.test.ts
│   ├── route-table.test.ts
│   ├── conflict.test.ts
│   └── store.test.ts
└── fixtures/mocks/                  # 单测与本地演示用示例数据（含 projects/）
```

导出形态（lack / Whistle 约定）：编译后 `dist/server.js`、`dist/uiServer/index.js`，`package.json` 的 `whistleConfig` 不需要列出 Hook 名——Whistle 按文件名加载 `server`、`uiServer`（lack 脚手架生成的入口即如此）。

`src/index.ts` 若采用单入口，则：

```ts
export { default as server } from './server';
export { default as uiServer } from './uiServer';
```

以 lack `lack init server,uiServer` 生成的目录为准，不要同时维护两套入口。

模块边界：

- `core/*` 禁止 `import` 任何 `Whistle.*` 类型。
- `server.ts` 只做适配：从 `req.originalReq` 取 method / host / path，调 `ProjectResolver` 与 `RouteTable.match`，再 `res.end` / `req.request` / `req.passThrough`。
- `uiServer` 只通过 `Store` 读写文件，不直接改 `RouteTable`；Store 变更后路由表重算。

共享状态：Whistle 在同一插件进程里调用两个 Hook，用模块单例 `createAppContext()` 保存 `Store` / 各项目 `RouteTable` / `mocksRoot`。不要把路由表塞进 `options.localStorage`（那是持久化 KV，不适合热路径）。

## 6. 数据层

文件协议与产品方案第 6 章一致，此处只补技术约定。

### 6.1 工作区绑定

```
mocksRoot = <用户选择的项目根>/mocks
```

解析顺序：

1. 插件 `localStorage` 键 `mocksRoot`（面板「选择工作区」写入）
2. P1：规则变量 `%scene-mock.dir=/abs/path`
3. 均无：不生成劫持规则，面板提示选择目录；`server` Hook 即使被界面 Rules 强行命中，也一律 `passThrough`

`localStorage` 用 `options.localStorage`（插件私有、重启保留）。不要用 `sharedStorage`。

校验：目录必须存在且可读；不存在则面板报错，不自动 `mkdir` 出一套空 mocks（避免绑错路径后污染磁盘）。首次使用提供「初始化 mocks 骨架」按钮，用户确认后再写 `config.json` 与空的 `projects/`。

### 6.2 配置文件字段

**全局 `mocks/config.json`**：

```json
{
  "matchPatterns": ["/api/"],
  "unmatched": "passthrough"
}
```

| 字段 | 说明 |
| --- | --- |
| `matchPatterns` | 与项目规则叠加的全局 pattern 列表，语法即 Whistle pattern；可为空数组 |
| `unmatched` | `passthrough`（默认）或 `404`。项目未配 `target` 时生效 |

**项目 `mocks/projects/<project-id>/project.json`**：

```json
{
  "name": "微贷后端",
  "host": "microcredit-ms-test-c.jhjj.paas.test",
  "target": "http://localhost:8889",
  "activeScenes": ["normal-order"]
}
```

| 字段 | 说明 |
| --- | --- |
| `name` | 展示名 |
| `host` | 被代理的域名。保存时规范化：去协议、去路径、小写；生成规则 `<host> scene-mock://`；全工作区唯一 |
| `target` | 代理到的域名。未命中该项目路由时 `req.request` 到该 origin（保留 path/query/body）；空表示走 `unmatched` 逻辑 |
| `activeScenes` | 与产品一致；建议 gitignore 或后期用 `project.local.json` 覆盖 |

**删除产品方案独立服务形态中的 `port`**。端口由 Whistle 管理，写了也无效。

### 6.3 写盘规则

- 所有写操作先校验 JSON schema，再 `writeFile` 原子替换（写 `*.tmp` + `rename`），避免半包文件被 watch 读到。
- 项目 id、接口 id、Scene 文件名（不含 `.json`）、variant 名：`^[a-zA-Z][a-zA-Z0-9_-]*$`，禁止 `/`、`..`、`.`，防止路径穿越。
- 项目 host 规范化后做全工作区唯一性校验；重复直接 409，响应里带冲突项目 id。
- 改项目 host：先校验唯一 → 改 `project.json` → 重算规则并 `updateRules()` → 重建该项目路由。顺序失败则整体回滚内存态并报错，不留半更新。
- 重命名 api-id：事务顺序为「`data/<old>/` 改名为 `data/<new>/` → 改该项目所有 `scenes/*.json` 的 `apis` 键 → 改 `apis.json` → 删旧目录」。中途失败在面板报「重命名未完成」，不静默半更新。
- 重命名 project-id：改目录名 → 重算规则。
- Scene JSON 与 data 文件落盘时 `JSON.stringify(doc, null, 2)`，保证 git diff 稳定。
- data 文件的内容就是响应体本身（object / array / string / number / bool / `null`），不要再包一层 `{ "body": ... }`。

### 6.4 内存模型

```ts
type ProjectDef = {
  id: string;                              // 目录名 projects/<id>/
  name: string;
  host: string;                            // 规范化后的被代理域名（小写、无协议）
  target: string;                          // 代理到的域名（origin），可为空
  activeScenes: string[];
};

type ApiDef = { id: string; method: string; url: string; desc?: string };

type SceneApiEntry = {
  status?: number;                         // default 200
  delay?: number;                          // ms, default 0
  headers?: Record<string, string>;
  data: string;                            // variant 名 → data/<apiId>/<data>.json
};

type SceneDef = {
  id: string;                              // 文件名 scenes/<id>.json
  name: string;
  desc?: string;
  apis: Record<string, SceneApiEntry>;     // api-id → 条目
};

type ResponseDoc = {
  status?: number;
  delay?: number;
  headers?: Record<string, string>;
  variant: string;
  body?: unknown;                          // 从 data 文件读入
};

type CompiledRoute = {
  projectId: string;
  apiId: string;
  sceneId: string;
  variant: string;
  method: string;
  pattern: string;
  regex: RegExp;
  staticScore: number;
  response: ResponseDoc;
};
```

`Store` 持有：

- `projects: Map<projectId, ProjectDef>`
- `hostIndex: Map<host, projectId>`（项目定位用，随项目增删改重建）
- 每个项目一份 `apis` / `scenes` / `dataIndex: Map<apiId, Map<variant, unknown>>`
- 每个项目一张 `RouteTable`

`RouteTable` 只包含：**该项目激活 Scene ∩ 条目含 `data` ∩ 对应 data 文件存在**。声明了接口但未设 `data`、或 variant 文件缺失 → 不进表（产品：不算生效路由，走未命中）。

合成（按项目）：

```
for sceneId in project.activeScenes:
  for [apiId, entry] of Object.entries(scene.apis):
    body = dataIndex.get(apiId)?.get(entry.data)
    if body === undefined: skip          // 文件不存在；合法 JSON `null` 仍进表
    emit CompiledRoute { projectId, ...entry, body, variant: entry.data }
```

### 6.5 隔离、复制与 fork

面板默认隔离，避免改一份 data 覆盖其它 Scene（产品 6.4）。Store 实现（全部在项目内）：

| 操作 | 行为 |
| --- | --- |
| 新建 Scene 条目 | 默认新建 `data/<api-id>/<variant>.json`。variant 优先用调用方传入的语义名；缺省用 `sceneId`，若已占用则 `sceneId-2`… |
| 复制其它 Scene | 复制源 data 文件为新 variant，再写入本 Scene 的 `data` 字段。不改为指向源文件 |
| 写 body | `usedBy.length > 1` → 先复制成新 variant、改本 Scene 引用，再写新文件（fork）。`usedBy.length <= 1` → 原地覆盖 |
| 显式共享 | 只改 Scene 条目的 `data` 指向已有 variant，不复制文件 |
| 删除 Scene | 只删 `scenes/<id>.json`；孤立 variant **不自动删**，详情接口返回 `orphans[]` 供面板提示清理 |
| 删除接口（force） | 从各 Scene 去掉该 api-id 键，并删除 `data/<api-id>/` |
| 删除项目 | 删除 `projects/<id>/` 整个目录；移除 `hostIndex` 项并重算规则 |

fork 后返回 `{ forked: true, variant }`，面板把路径切到新文件。手改共享 data 文件不走 fork（热加载按引用全部生效），面板顶部可提示引用计数。

## 7. 项目定位与匹配引擎

### 7.1 项目定位（ProjectResolver）

输入：`req.fullUrl` 的 host（小写、去端口）。Whistle 已把 HTTPS 解成明文 URL，**不要用 Host 头拼 path**。

1. `hostIndex.get(host)` 命中 → 返回该项目
2. 未命中（请求由 `matchPatterns` 前缀带进来，host 不属于任何项目）→ 不归入任何项目，在 `status` 里记一条 `unresolvedHosts[]` 供面板提示，请求走 `passThrough`
3. 项目已停用 → 视为未绑定，走 `passThrough`

host 带端口时先整值查、再去端口查（项目 host 一律不带端口存储）。

### 7.2 项目内接口匹配

输入：`method`、`pathname`（不含 query）。规则（与产品 7.1 一致）：

1. method 大小写不敏感精确相等
2. path 匹配 URL 模式；`:param` 只吃单段 `[^/]+`；模式必须整段匹配（`^...$`）
3. 忽略 query
4. 不匹配 host（host 已经在项目定位阶段用掉）

编译：

```
/api/users/:id  →  ^/api/users/([^/]+)$
```

冲突优先级（同项目内不同 api-id 模式重叠）：

1. `staticScore` 大者胜（静态段数量，`/api/users/me` > `/api/users/:id`）
2. 同分：`apis.json` 中先出现者胜
3. 同分且并存时，面板 `status.ambiguousRoutes` 提示，**不弹 Scene 冲突窗**

`:param` 一期只用于匹配，不注入 body（动态模板是 P2）。

复杂度：单项目生效路由通常几十～几百条，线性扫描足够。路由表在激活/热加载时编译一次，请求路径只做 `regex.test`。

## 8. server Hook：请求处理

签名与官方一致：

```ts
export default (server: Whistle.PluginServer, options: Whistle.PluginOptions) => {
  server.on('request', handleHttp);
  server.on('upgrade', (req, socket) => req.passThrough()); // 一期 WebSocket 透传
  server.on('connect', (req, socket) => req.passThrough()); // tunnel 不处理
};
```

### 8.1 HTTP 处理流程

```
request
  │
  ├─ 无 Store（未绑定工作区） → passThrough
  ├─ ProjectResolver(req.host) → project（无 → passThrough）
  ├─ project.RouteTable.match(method, pathname)
  │     ├─ hit → drain(req) → wait(delay) → writeHead + end(body)
  │     └─ miss
  │           ├─ project.target 非空 → req.request(upstream) 管道转发
  │           ├─ unmatched=404       → 404 JSON
  │           └─ 默认                → req.passThrough()
```

**必须先 drain 请求体**再结束响应（官方 `whistle.test-server` 的 `drain` 模式）。否则客户端 POST 可能挂起。

mock 响应：

```ts
const status = response.status ?? 200;
const headers = { 'content-type': 'application/json', ...response.headers };
headers['x-scene-mock'] = `${projectId}/${sceneId}/${apiId}/${variant}`;  // 便于 Network 一眼看出走了 mock
const body = serialize(response.body, headers['content-type']);
```

`delay` 用 `setTimeout`，只作用于 mock 命中；透传不额外加延迟。延迟期间不阻塞其它请求（每个 request 独立）。

### 8.2 透传两种实现

**A. `req.passThrough()`（项目未配 target 且 unmatched=passthrough）**

Whistle 继续访问 `fullUrl` 原始目标。这是混合联调的主路径，也是相对独立 `:3456` 方案最大的简化。

**B. `req.request()` + pipe（项目配了 target）**

把请求打到 `project.target + pathname + search`。实现注意：

- 去掉 hop-by-hop：`Connection`、`Keep-Alive`、`Transfer-Encoding`、`TE`、`Trailer`、`Upgrade`、`Proxy-Authorization`、`Proxy-Authenticate`
- `Host` 改为 `target` 的 host
- 保留 `Cookie`、`Authorization`
- 超时 30s；失败 `502`，body 为 `{ error: 'proxy_failed', message }`
- HTTPS 上游用 Whistle 提供的 `req.request`，不要自己再起 undici 绕过代理证书

WebSocket / CONNECT 一期直接 `passThrough`，与产品边界「不做 WebSocket」一致。

### 8.3 响应体序列化

| Content-Type | body 类型 | 输出 |
| --- | --- | --- |
| `application/json`（默认） | 任意 JSON 值 | `JSON.stringify` |
| `text/*` | string | 原样 |
| 其它 | string 或已是 string 的 JSON | 若非 string 则 stringify |

非法 `delay`（负、NaN）按 0；`status` 非 100–599 按 200，并记入热加载警告（文件仍服务，不丢）。

## 9. 规则下发

### 9.1 生成内容

`src/rules.ts` 根据 `matchPatterns` + 所有可用项目的 `host` 生成插件根目录 `rules.txt`：

```
# generated by whistle.scene-mock — do not edit
/api/ scene-mock://
microcredit-ms-test-c.jhjj.paas.test scene-mock://
```

matchPatterns 在前、项目 host 在后，去重（`rulePatterns()`）。pattern 原样写出，**不在插件里实现 Whistle 的 pattern 解析**——那是 Whistle 的事。项目 `project.json` 损坏导致项目停用时，该项目的 host 不进规则。

生成后调用 `options.updateRules()`，使新规则生效而无需重装插件。

### 9.2 何时更新

- 绑定 / 更换 `mocksRoot`
- 项目新建 / 删除 / 修改 `host`
- `config.json` 的 `matchPatterns` 变化（面板保存或热加载）
- 插件启用时做一次

**不**在 Scene 激活时更新。切 Scene 只改内存 `RouteTable`。

### 9.3 空规则

未绑定工作区，或 `matchPatterns` 与项目 host 都为空：`rules.txt` 只保留注释。此时只有用户在界面 Rules 手写 `xxx scene-mock://` 才会进 `server` Hook。

### 9.4 与「复制规则」并存

面板仍提供「复制 whistle 规则」（产品 P0），文案改为：

- 默认：插件已自动写入 `rules.txt`，一般不用粘贴
- 若界面 Rules 里有更高优先级的同 pattern，复制内容给用户手动对齐

复制文本示例：

```
# scene-mock · 短协议才会进插件 server
# 插件禁用后这条（以及插件 rules.txt）都失效
/api/ scene-mock://
microcredit-ms-test-c.jhjj.paas.test scene-mock://
```

#### 10.2.1 通用约定


### 10.3 SSE

`text/event-stream`，事件：

- `reload`：文件已热加载，面板重拉列表（载荷带 `projectId`，面板只刷新受影响项目）

## 11. 热加载、错误与进程稳定性

监听 `mocksRoot` 递归（Node 18+ `fs.watch({ recursive: true })`，macOS / Windows 可用）。事件合并 **150ms debounce**，目标「保存后 200ms 内对新请求生效」。

按文件类型增量重载：

| 路径 | 动作 |
| --- | --- |
| `config.json` | 重载 matchPatterns / unmatched；patterns 变则 `updateRules()` |
| `projects/<pid>/project.json` | 重载该项目配置；host 变则重建 `hostIndex` 并 `updateRules()`；activeScenes 变则重编译该项目路由 |
| `projects/<pid>/apis.json` | 重载该项目接口池，重编译该项目全表 |
| `projects/<pid>/scenes/*.json` | 重载该 Scene（文件名 = scene-id）；重算引用计数并重编译相关路由 |
| `projects/<pid>/data/<api-id>/<variant>.json` | 更新 `dataIndex`；替换所有引用该 variant 的 `CompiledRoute.response.body` |
| `projects/` 下目录或文件增删 | 重建项目列表 / Scene 列表 / dataIndex，再按需重编译 |

坏文件策略（产品 6.6）：

- 解析失败 / schema 失败：**保留上一份合法内存快照**继续服务
- 把 `{ relativePath, reason }` 放进 `Store.errors`，SSE 推 `error`，面板顶部展示
- **不**抛出到 Hook 外；Whistle 文档说明插件未捕获异常不会打崩 Whistle，但仍应自己 catch，避免当前请求 500 且无说明
- 单个 data 文件损坏：只影响引用它的接口；其它 Scene / variant / 项目继续服务
- 某个 `scenes/<id>.json` 损坏：只停用该 Scene（从路由表去掉），其它 Scene 继续
- 某个 `project.json` 损坏：只停用该项目（host 出规则、路由清空、透传回源），其它项目继续
- `config.json` 从未成功加载过：绑定失败，面板不可操作 mock，`rules.txt` 不劫持（避免空路由静默跑）

`project.json` 里 `activeScenes` 自相冲突（手改或 git merge）：

- 拒绝使用该激活集合
- 该项目 `RouteTable` 清空（该项目全部透传），避免歧义 mock
- SSE `conflict`，面板强制解决后再写回合法 `activeScenes`

## 12. 激活与冲突

实现放在 `core/conflict.ts`，uiServer 只负责把结果变成 409 + 弹窗。所有判定都在 `:pid` 对应的项目内进行。

`POST /cgi-bin/projects/:pid/activate`：

1. 计算 `newApis = Object.keys(scene.apis)` 中「`data` 已设且 data 文件存在」的集合
2. 与该项目每个已激活 Scene 求 api-id 交集
3. 无交集：`project.activeScenes.push`，写盘，重建该项目路由表，200
4. 有交集：不改盘，409

```json
{
  "error": "scene_conflict",
  "projectId": "microcredit",
  "incoming": { "id": "order-error", "name": "下单异常流" },
  "conflicts": [
    {
      "apiId": "get-orders",
      "method": "GET",
      "url": "/api/orders",
      "existingScene": { "id": "normal-order", "name": "正常下单", "status": 200, "preview": "{...}" },
      "incomingScene": { "status": 500, "preview": "{...}" }
    }
  ],
  "closeScenesIfKeepNew": ["normal-order"]
}
```

`preview`：对应 data 文件 JSON.stringify 截断到 200 字符。冲突比较的是「激活后会生效的合成响应」，不是 Scene JSON 本身。

`POST /cgi-bin/projects/:pid/activate/resolve`：

- `keep-new`：从该项目 `activeScenes` 去掉 `closeScenesIfKeepNew`（仅冲突的旧 Scene），加入新 Scene；无交集的已激活 Scene 不动
- `keep-old`：不改 `activeScenes`

不做按接口拆分。`deactivate` 直接删 id。

并发：激活用 Store 上的异步互斥队列（同一工作区串行写 `project.json`），防止双击开关写出交错数组。

## 13. Web 面板实现要点

| 项 | 选择 |
| --- | --- |
| 框架 | React 18 + Vite |
| 路由 | HashRouter（`#/projects`），避免插件子路径 history 问题 |
| `base` | `'./'` |
| UI | 轻量组件即可，对齐已有原型屏幕，不引入重型设计系统 |
| JSON 编辑 | textarea + `JSON.parse` 校验；P1 再换 CodeMirror |
| 实时 | SSE + 失败时 3s 轮询 `/cgi-bin/status` |

页面结构与路由（项目为第一层导航）：

| 产品屏幕 | 路由 |
| --- | --- |
| 项目管理 | `#/projects`（列表 + 新建/编辑/删除，从每行进入 Scene / 接口池） |
| Scene 管理 | `#/projects/:pid/scenes`；无 pid 的 `#/scenes` 为跨项目聚合列表（查询项：项目名称、Scene 名称），从行操作进入对应项目管理 |
| Scene 详情 | `#/projects/:pid/scenes/:id` |
| 接口池 | `#/projects/:pid/apis`；无 pid 的 `#/apis` 为跨项目聚合列表（查询项：项目名称、接口关键词） |
| 响应编辑器 | `#/projects/:pid/scenes/:id/apis/:apiId`（详情上的抽屉或子页均可）。展示 Scene 文件路径、data 文件路径、variant 引用计数；保存 body 走 fork |
| 冲突弹窗 | 全局 Modal，由 409 / SSE 驱动 |
| 全局配置 | `#/config` |

全局配置页按卡片分区（对齐原型 `prototype/config.pen`）：

1. **工作区**：绑定 / 初始化 mocks 目录、最近路径、当前监听状态
2. **匹配规则**：全局 `matchPatterns`、复制 whistle 规则（含全部项目规则）
3. **运行时**：各项目激活 Scene、HTTPS 抓包状态、热加载错误、孤立 variant、未识别 host 提示

项目管理已收拢为独立一级导航 `#/projects`，配置页不再承载项目的新建 / 编辑 / 删除，避免双入口。

工作区未绑定：所有页上方固定条，仅配置页可操作「选择目录」。目录选择：输入绝对路径（插件 uiServer 没有系统文件框权限）；可做最近路径列表（`localStorage`）。

破坏性操作（删项目、删接口、删 Scene）二次确认。删项目列出其下 Scene / 接口 / data 统计；改 api-id 单独做成「重命名」并展示将改动的文件列表（`apis.json`、各 Scene、`data/<id>/`）；改项目 host 提示「将同步改写 whistle 规则」。删 Scene 不自动删孤立 data，确认框列出将残留的 variant。

## 14. 与产品方案的差异

产品语义不变。运行时形态有意调整：

| 点 | 产品方案 | 本技术方案 | 原因 |
| --- | --- | --- | --- |
| 进程 | 独立 Node `:3456` | Whistle 插件进程 | 用官方 `server` Hook，免端口与转发丢 host（项目定位依赖原始 host） |
| 管理入口 | `http://127.0.0.1:3456/` | `/plugin.scene-mock/` | uiServer Tab |
| 管理 API | `/__admin/*` | `/cgi-bin/*` | 与业务流量物理隔离，遵循插件惯例 |
| 未命中默认 | 无 target → 404 | `passThrough` 回源 | 插件仍持有 `fullUrl` |
| `config.port` | 有 | 删除 | 无独立监听端口 |
| 项目 host 规则 | 复制粘贴 | 与 matchPatterns 一起自动写入 `rules.txt` | 插件可自动加载规则 |
| 未知 host 处理 | 未定义 | 不归入任何项目，透传并在状态页提示 `unresolvedHosts` | 多项目并存时「当前项目」语义已移除，归属不再依赖面板状态 |
| 启动命令 | `npx scene-mock` | 安装/挂载插件 + `lack watch`（开发） | 生命周期归 Whistle |
| 一期「不自动改 Whistle 配置」 | 只复制 | 改插件自己的 `rules.txt`，不改用户界面 Rules | 仍不碰用户规则文件 |

项目 `target` 即产品「代理到的域名」，替代早期全局 `proxyTarget`：每个项目各自指上游，互不干扰。

## 17. 测试策略

| 层 | 范围 | 不测 |
| --- | --- | --- |
| core 单测 | project（host 规范化 / 唯一性 / host→项目解析，未知 host 透传并记录 unresolvedHosts）、matcher 表（产品 7.1 用例）、route-table 按项目合成（缺 data 文件不进表）、conflict 二选一（项目内）、坏 JSON 保留快照、项目 / api-id 重命名事务、复制=新文件、共享 variant 写 body 时 fork | Whistle 进程 |
| uiServer 契约 | 用注入的内存 Store 打 `/cgi-bin/*`，覆盖 409/412；项目 CRUD 与规则重算触发 | 浏览器 |
| 手工 / 冒烟 | `lack watch` + 浏览器走一遍验证清单 | CI 里起 Whistle（一期不做） |

matcher 最小用例：

- `GET /api/users/1` vs `GET /api/users/:id` → 命中
- `GET /api/users` vs `GET /api/users/:id` → 不命中
- `GET /api/orders?page=1` vs `GET /api/orders` → 命中
- `POST /api/orders` vs `GET /api/orders` → 不命中
- `/api/users/:id` 与 `/api/users/:userId` 同分 → 接口池先注册者 + 歧义标记

project 最小用例：

- `HTTP://Microcredit-ms-test-c.jhjj.paas.test/` 注册 → 规范化为小写 host
- 两项目同 host → 第二个 409
- 未知 host 请求 → 不归属任何项目，记录 `unresolvedHosts` 后 passThrough
- 改项目 host → `hostIndex` 重建且规则文本同步变化

## 18. 一期实现拆分

建议顺序，每步都可 `lack watch` 验证：

| 步 | 交付 | 验收 |
| --- | --- | --- |
| 1 | lack 脚手架 + `server` 对 `scene-mock://` 固定返回 hello | 界面规则 `example.com scene-mock://` 能打到插件 |
| 2 | `core/store` + 绑定工作区 + 读 `config.json` / `projects/*` | 单测 + 面板能列出项目 |
| 3 | `core/project`：项目 CRUD + host 唯一性 + `hostIndex` | host 重复 409；改 host 规则文本变化 |
| 4 | `matcher` + 按项目 `route-table` + server 真正 mock | 激活后接口返回 JSON，含 delay |
| 5 | miss → 项目 target / passThrough / 404 | 未覆盖接口行为符合项目与全局 config |
| 6 | `rules.txt` 生成（matchPatterns + 项目 host）+ `updateRules` | 绑定后不必手写规则即可劫持项目域名 |
| 7 | Scene/接口/返回值 CRUD API + 面板页面 + fork | 不打开编辑器能完成日常联调；共享数据从面板改会复制新文件 |
| 8 | 激活冲突 409 + 弹窗二选一 | 有交集必须确认；无交集并行 |
| 9 | watch + 坏文件 + SSE | 改 JSON 保存即生效；坏文件不拖垮 |

P0 不包含：命中日志、OpenAPI 导入、CLI、`X-Mock-Scene`、Network 列扩展。

## 19. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 用户误用长协议 `whistle.scene-mock://`，`server` 收不到请求 | `hideLongProtocol: true`；复制规则只给短协议；文档强调 |
| `rules.txt` 写进 npm 全局目录失败（权限） | 失败则面板展示错误，并降级为「只复制规则」；不静默 |
| 界面 Rules 里已有同 host / `/api/ file://...`，优先级盖过插件 | 配置页检测并提示「界面规则优先」；不自动改用户 Rules |
| 项目 host 重复导致路由歧义 | 保存即 409；热加载发现重复时后加载项目停用并提示 |
| matchPatterns 前缀过宽，未知 host 全进插件 | 未知 host 不归属任何项目、透传并在状态页提示；未命中默认 `passThrough`，源站仍可用 |
| 项目 target 配错，该域名未 mock 接口全挂 | 项目卡片强提示 target 含义；透传失败给 502 不是空白 |
| HTTPS 未开抓包，插件只能看到 CONNECT | 配置页检测 `options.getHttpsStatus`，未开启则横幅提示 |
| `fs.watch` 在部分 Linux 无 recursive | 对 `projects/` 逐层（项目 / scenes / data）逐目录 watch；或 P1 再引入 chokidar |
| 工作区路径绑错 | 不自动创建 mocks；展示将监听的绝对路径，确认后才 watch |
| 共享 variant 被手改 | 热加载按引用全部生效（与面板 fork 不同）；面板展示 refCount，手改路径旁提示 |
| `activeScenes` 被 commit 互相覆盖 | README 约定不提交该字段；P1 `project.local.json` |
| 插件热重载丢内存态 | 激活态以磁盘 `project.json` 为准，重载后重新 `Store.load` |
| 相对路径被 Vite 打成 `/assets/xxx` | `base: './'`；CI 检查 `web/dist/index.html` 不含以 `/assets` 开头的引用 |
